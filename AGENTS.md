## UPSTREAM DISTILLATION

### Scope and ownership

This is generated, device-specific proprietary payload for infiniti. It owns packaging of extracted ODM/product/vendor files and radio firmware; it does not own the open interfaces or policy that consume those artifacts. Source declarations live in `device/oneplus/infiniti/proprietary-files.txt` and `proprietary-firmware.txt`.

### Build graph and layout

- `infiniti-vendor.mk` is generated and maps payload paths into Android partitions. `Android.mk`, `Android.bp`, and `BoardConfigVendor.mk` package generated modules and board inputs.
- `proprietary/odm/` contains device calibration and configuration, including panel, audio, camera, sensor, and init data.
- `proprietary/product/` and `proprietary/vendor/` contain partition-scoped applications, libraries, services, firmware, and configuration.
- `radio/` contains boot-chain and modem firmware images. These are payload bytes, not a place for source edits.
- `.lfsconfig` marks this as an LFS-backed repository. A pointer file is not a hydrated blob and must not be mistaken for valid payload content.

### Interface, build, and sepolicy boundaries

No open AIDL/HIDL API or sepolicy policy is authored here. Generated build stanzas may describe prebuilt shared libraries, apps, and required modules; their interface declarations, service ownership, init policy, VINTF, and SELinux rules belong in the corresponding open source/device projects. A removed or added service blob must be reconciled with those declarations.

### Extension precedents

Lineage/crDroid integration occurs by deblobbing an interface where an open implementation exists, retaining only required backend payload, and updating the device extraction list plus generated tree as one paired change. Do not surface binary symbols, firmware revisions, panel IDs, or filesystem paths as new product APIs.

### Conventions and verification

`infiniti-vendor.mk` says `Automatically generated file. DO NOT MODIFY` and is regenerated by the device extraction workflow. Upstream subjects use `infiniti: <imperative description>` and update commits name their OOS source. Verify declaration-to-payload coherence in both directions, LFS hydration, ELF dependencies for changed prebuilts, and exact partition destinations. Never hand-edit binary payload bytes or generated package lists.
